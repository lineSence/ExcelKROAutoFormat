# Обновление по кнопке (OTA)

Страница `Обновление` (`/update`) ставит на сервер выбранную версию из Git:
забирает код, доставляет зависимости и перезапускает службу.

## Как это устроено

Служба `excelkro` может работать как от отдельного пользователя, так и от `root`
(текущий VPS владельца развёрнут вручную и работает от `root`). Поэтому OTA
определяет фактического пользователя основной службы и выполняет обновление
через отдельную разовую службу `excelkro-update@<режим>`.

1. веб-слой вызывает `systemctl start --no-block excelkro-update@<режим>.service`;
2. служба запускает `bash deploy/ota-update.sh` под root в своём окружении;
3. скрипт пишет ход работы в `/var/lib/excelkro/update/update-state.json` и `update.log`;
4. страница читает состояние и обновляется сама каждые 5 секунд, пока работа идёт.

Отдельная служба нужна и по второй причине: при перезапуске веб-слой умирает. Если
запустить обновление дочерним процессом, оно оборвётся на полпути.

Скрипт запускается именно через `bash`, а не напрямую. `git reset --hard` возвращает
файлам права из репозитория и может снять выставленный вручную флаг `+x`; запуск
через `bash` от него не зависит.

## Выбор ветки

На странице `/update` есть поле **«Ветка обновления»**. В него попадают:

- ветки `origin/*` из локального Git-кеша;
- локальные ветки;
- `main` — всегда присутствует как безопасная точка возврата.

Выбранная ветка сохраняется в `${UPDATE_DIR}/selected-branch`; по умолчанию это
`/var/lib/excelkro/update/selected-branch`. Файл создаётся с правами `0600` и
записывается атомарно.

Перед сохранением имя ветки проверяется. Разрешается безопасный набор символов Git
ref; запрещены `..`, начальный `/` или `-`, конечный `/` и пустые значения. После
проверки ветка должна существовать среди известных локальных или `origin`-веток.

**Выбор ветки влияет непосредственно на обновление:**

- `check` выполняет `git fetch` и сравнивает текущую сборку с выбранной веткой;
- `apply` переводит рабочее дерево на `FETCH_HEAD` выбранной ветки, ставит зависимости,
  при необходимости обновляет systemd unit и перезапускает `excelkro`.

Это означает, что выбор `fix/p0-hardening` действительно переводит сервер на эту
ветку. Для возврата на стабильную ветку выберите `main` и выполните установку.

Состояние OTA хранит имя ветки. Если сохранённый результат относится к другой ветке,
его `behind` не используется для новой выбранной ветки — это предотвращает показ
старого результата как актуальной проверки.

## Режимы

- `check` — кнопка «Проверить обновления»: только `git fetch` и сравнение сборок.
  Файлы программы и зависимости не меняются, служба не перезапускается.
- `apply` — кнопка «Установить выбранную версию»: `git reset --hard` на `FETCH_HEAD`,
  `pip install -r requirements.txt`, при необходимости обновление `app.service`
  и `excelkro-update@.service`, `systemctl restart excelkro` и проверка `/health`
  до 20 секунд.

Если новых коммитов нет, `apply` ничего не делает и пишет об этом в состояние.

Описание службы обновления переставляется автоматически только при стандартных
путях (`/opt/excelkro`, `/var/lib/excelkro/update`). На нестандартной установке
после изменения unit-файла нужен `install-ota.sh`.

## Данные при обновлении

Остаются на месте: справочники, реестр расхождений, примеры обучения, модель — они
живут вне папки кода (`/var/lib/excelkro`).

Теряются: незаконченные сверки, ссылки на скачивание и подтверждённые фото — они
хранятся в памяти процесса. Поэтому кнопка спрашивает подтверждение.

## Установка на сервере

На новом сервере всё делает `deploy/install.sh`.

Если сервер разворачивался вручную и частей OTA на нём нет (страница пишет «Служба
обновления не установлена»), достаточно одной команды:

```bash
sudo bash /opt/excelkro/deploy/install-ota.sh
```

Скрипт трогает только части обновления: ставит unit, при необходимости правило sudo,
создаёт папку состояния и перечитывает `systemd`. Саму программу и пользовательские
данные он не меняет.

Если служба работает от `root`, правило sudo не требуется: программа запускает
`systemctl` напрямую. Это нормальный режим для ручного развёртывания текущего VPS.

## Если папка программы не копия Git

При развороте через `deploy/deploy.sh` код приезжает через rsync, и `.git` нет. Тогда
кнопка отключена и на странице видно предупреждение. Переход одноразовый:

```bash
sudo systemctl stop excelkro
sudo mv /opt/excelkro /opt/excelkro-old
sudo git clone https://github.com/lineSence/ExcelKROAutoFormat.git /opt/excelkro
sudo cp -r /opt/excelkro-old/venv /opt/excelkro/venv
sudo bash /opt/excelkro/deploy/install.sh
```

## Проверка и разбор ошибок

- готовность частей OTA видна на странице «Обновление» и в `parts` ответа
  `curl -sS http://127.0.0.1:8000/update/state`;
- журнал скрипта: `/var/lib/excelkro/update/update.log`;
- журнал службы обновления: `journalctl -u excelkro-update@apply`;
- журнал программы: `journalctl -u excelkro -n 100`.

Для текущего VPS, работающего от root, проверка `sudo -u excelkro …` не применяется:
пользователя `excelkro` на сервере может не существовать.

Если старый unit всё ещё содержит `ExecStart=/opt/excelkro/deploy/ota-update.sh %i`
без `bash`, обновите описание одной командой:

```bash
sudo bash /opt/excelkro/deploy/install-ota.sh
```
