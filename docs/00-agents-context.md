# Протокол работы со знанием (SEK)

Знание проекта растёт само, но по правилам. Этот файл описывает
именно процедуру, а не содержание правил.

## Уровни

| Уровень | Файлы | Когда читается |
| --- | --- | --- |
| L0 | `agents_context.md` | всегда, целиком |
| L1 | `docs/_routing.md`, `docs/_index.md`, этот файл | всегда перед работой |
| L2 | `docs/rules/*`, `docs/references/*`, `docs/01–13-*` | по триггерам из `_routing.md` |
| L3 | `docs/memory/inbox.md`, `docs/memory/journal.md` | при записи и разборе наблюдений |

Порядок работы: прочитать L0 → подобрать триггеры в `_routing.md`
→ прочитать только нужные файлы L2 → сделать работу → записать,
что узналось. Всё знание сразу не читается никогда.

## Зрелость записи

- `draft` — одно наблюдение, живёт в `docs/memory/inbox.md`.
  На него нельзя ссылаться как на правило.
- `validated` — повторилось или подтверждено кодом. Живёт в
  `docs/rules/`. При расхождении с кодом главнее код.
- `core` — требование владельца. Нарушение считается регрессией:
  правило главнее кода, код подлежит исправлению.

## Что агент делает сам

1. Пишет наблюдения в `docs/memory/inbox.md` без спроса — по четырём
   триггерам: неожиданное поведение, найденный обходной путь,
   расхождение внешнего сервиса с документацией, поправка владельца.
2. Продвигает запись из `inbox` в `docs/rules/` со зрелостью `validated`,
   присваивает тег, удаляет запись из `inbox` и пишет строку в
   `docs/memory/journal.md`.
3. Поправляет `docs/_index.md` и `docs/_routing.md`, если появился или
   исчез файл знания.
4. Сообщает о своих действиях со знанием одной строкой:
   - `📚 Promoted: [TAG] → docs/rules/…` — после промоута;
   - `🆕 Using recently promoted: [TAG]` — когда новое правило
     применяется впервые.

## Что требует «да» владельца

- Перевод правила из `validated` в `core`.
- Изменение или отмена любого `core`-правила.
- Предметные величины: пороги, цвета, состав столбцов.
- Новые внешние сервисы и новые зависимости сервера.

## Отмена: `/revoke [TAG]`

По команде владельца агент удаляет правило из `docs/rules/`, пишет
строку `revoke` в журнал с основанием и больше на него не
ссылается. Если правило было завязано на тест, тест удаляется
тем же коммитом.

## Целостность

`tests/test_sek.py` проверяет: все файлы из `_routing.md` и `_index.md`
существуют; теги правил уникальны; у каждого правила есть строка
зрелости; в `inbox.md` не больше 50 записей.
