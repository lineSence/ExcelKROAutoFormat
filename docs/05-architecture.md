# 5. Архитектура и развёртывание

Решение: веб-приложение на Python на сервере Ubuntu Server. Установка через SSH одной командой. Доступ к сайту только через SSH-туннель.

## 5.1 Сценарий работы пользователя

1. Пользователь открывает туннель и заходит на `http://localhost:8000`.
2. Загружает файл сверки из 1С. Имя файла важно: из него берётся имя склада.
3. Сайт ремонтирует файл, разбирает блоки групп и применяет форматирование.
4. Сайт отдаёт готовый файл на скачивание и показывает отчёты.
5. Остальные данные человек вписывает в Excel вручную.

Имя выходного файла: `<Склад> <ДД.ММ.ГГГГ>.xlsx`. Склад — из имени входного файла, дата — из титула файла 1С.

## 5.2 Состав приложения

| Слой | Назначение | Инструмент |
| --- | --- | --- |
| веб-слой | одна страница: загрузка, выдача файла, отчёты | FastAPI + Jinja2 |
| ядро | ремонт файла, разбор, форматирование | `openpyxl` |
| сервер приложения | запуск и автостарт | Uvicorn под systemd |

Базы данных нет. Nginx нет. Входа по паролю нет.

Ядро не зависит от веб-слоя. Его надо вызывать и из командной строки для тестов.

Ремонт файла делается работой с архивом `.xlsx` средствами стандартной библиотеки (`zipfile`). Внешних программ основной путь не требует.

## 5.3 Обработка файлов и безопасность

1. Файлы обрабатываются во временном каталоге (`TMP_DIR`).
2. Входной и выходной файлы удаляются сразу после выдачи ответа.
3. Служба слушает только `127.0.0.1:8000`. Извне сервер порт не отдаёт.
4. Предельный размер загрузки задаётся настройкой `MAX_UPLOAD_MB`.
5. Логи идут в journald без содержимого файлов.

## 5.4 Структура репозитория (план)

```
app/
  main.py            веб-маршруты
  core/
    repair.py        ремонт xlsx из 1С
    parse.py         поиск блоков групп
    resort.py        грозди брендов и разбор пересортов
    format.py        форматирование и формулы
    style.py         цвета, рамки, ширины
    report.py        отчёты по группам и гроздям
  templates/         страница загрузки и отчётов
  static/            стили
deploy/
  install.sh         установка на сервере
  deploy.sh          запуск установки через ssh
  app.service        юнит systemd
  tunnel.sh          открытие SSH-туннеля
  .env.example       настройки
tests/
  data/              примеры входа и выхода
docs/
requirements.txt
```

## 5.5 Установка

Одна команда на рабочей машине:

```bash
./deploy/deploy.sh user@server
```

Шаги скрипта `install.sh` на сервере:

1. Проверка версии Ubuntu и прав `sudo`.
2. Установка пакетов: `python3`, `python3-venv`. LibreOffice не нужен; он ставится только при `REPAIR_MODE=libreoffice`.
3. Создание служебного пользователя и каталога `/opt/excelkro`.
4. Копирование кода и создание виртуального окружения.
5. Установка зависимостей из `requirements.txt`.
6. Запись `.env` из образца `deploy/.env.example`.
7. Установка юнита systemd и автозапуск.
8. Проверка работы: запрос к `http://127.0.0.1:8000/health`.
9. Вывод команды для туннеля.

Требования к скриптам:

- Повторный запуск безопасен (идемпотентность).
- Обновление версии той же командой.
- Все настройки в `.env`, без правки кода.

## 5.6 Доступ через SSH-туннель

Команда на рабочей машине:

```bash
ssh -N -L 8000:127.0.0.1:8000 user@server
```

Затем в браузере: `http://localhost:8000`.

Скрипт `tunnel.sh` делает то же самое одной командой. Для Windows та же команда работает в PowerShell с встроенным OpenSSH.

## 5.7 Тесты

1. Проверка ремонта файла из 1С: файл открывается, стили и ширины не изменились.
2. Проверка поиска блоков на двух примерах (ОхтаМоллСМА и БалтийскийТЦМДБ).
3. Проверка разбора гроздей: состав грозди и решение по каждой строке.
4. Сравнение результата с образцом: адреса формул, цвета, ширины столбцов, автофильтр.
5. Проверка имени выходного файла.
6. Проверка удаления временных файлов.
