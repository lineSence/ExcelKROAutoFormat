# Правила: веб-слой (`WEB-*`)

Зрелость: `validated`. Все пункты выросли из реальных багов,
см. `docs/references/known-issues.md`.

## `[WEB-ROUTER]` Новый маршрут — в своём роутере

Маршрут живёт в `app/web/routers/*` и подключается через `ROUTERS`
в `routers/__init__.py`. Общая память и зависимости берутся из
`app/deps.py`, а не создаются заново.

## `[WEB-NAV]` Раздел без обработчика не коммитится

Шаблоны — Jinja2 без фронтенд-сборки, наследование от `base.html`.
Новый раздел = шаблон + запись в `nav_items`, причём только вместе
с работающим маршрутом — иначе пункт меню отвечает 404.
Служебные страницы (`progress.html`) в `nav_items` не попадают.

## `[WEB-POST-303]` Действия — POST, потом редирект 303

Образец — `/training`. Если на странице нужно показать результат
действия, страница рисуется сразу, без редиректа.

## `[WEB-REFRESH-URL]` В теге автообновления нужен явный `url=`

`<meta http-equiv="refresh">` без `url=` после POST даёт
`{"detail":"Method Not Allowed"}`. На `/update` обязателен `url=/update`.
Исключение — страница хода разбора: адрес свой же и пришли на него
по GET.

## `[WEB-TOKEN-FIELD]` Скрытое поле `token` обязательно

Без него запись в файл молча не происходит. Касается всех форм,
работающих с конкретной сверкой. У раздела почты токена нет:
ящик один на службу.

## `[WEB-THREADPOOL]` Долгая работа — не в `async def`

Разбор файла, сеть и почта уходят в отдельный поток: либо
синхронный обработчик, либо `run_in_threadpool`. Блокирующий код
внутри `async def` запрещён.

## `[WEB-BACKGROUND]` Работа дольше запроса — фоновая задача с билетом

`POST /upload` только сохраняет файлы, заводит билет (`progress.start`)
и отвечает редиректом 303 на `/upload/progress/{билет}`. Разбор идёт в
`services/upload_job.py`. Ответать пользователю после всех шагов
нельзя: это выглядит бесконечной загрузкой.

## `[WEB-STAGES]` Порядок этапов задаёт веб-слой

`UPLOAD_STAGES`: «Файл принят» → «Разбор сверки» → «Пометки „нет фото“»
→ «Снимки из писем». Проценты — доля закрытых этапов, поэтому
порядок важен. Сверка кладётся в память сразу после сборки файла,
не дожидаясь необязательных шагов; сбой необязательного этапа не
роняет сверку (`progress.stage_failed`).

## `[WEB-NO-500]` Ошибка становится текстом на странице

Обработчик не должен падать с Internal server error: ошибка внешней
службы превращается в понятное сообщение (образец — `mail.check()`).
После перезапуска страница хода честно отвечает «разбор не найден».

## `[WEB-STATE-MEMORY]` Состояние живёт в памяти процесса

`jobs`, `letters`, `exports`, `progress` — в памяти. Перезапуск стирает
их, об этом предупреждаем на странице обновления. Следствие: служба
работает в одном воркере, фоновому сбору почты некуда складывать
результат, письма забираются только по кнопке.

## `[WEB-ATOMIC-FILE]` Файл для компаньона пишется атомарно

Сначала `*.part`, потом `replace`. Входящий файл из папки берётся
только после того, как размер и время не менялись `stable_seconds`.
