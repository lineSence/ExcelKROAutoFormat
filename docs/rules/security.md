# Правила: безопасность доступа (`SEC-*`)

Код — `app/security.py`, `app/deps.py`, `app/web/routers/companion.py`.
Строка под заголовком всегда несёт зрелость, дату и источник.

## `[SEC-NO-SECRETS]` В репозитории нет ключей и данных сверок

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

Ключи моделей, пароли почты, файлы сверок, снимки и выгрузки не
попадают в git ни в каком виде — ни в коде, ни в тестах, ни в
документации, ни в примерах настроек. Нарушение = регрессия.
Состояние живёт только в `/var/lib/excelkro`.

## `[SEC-AUTH-ALWAYS]` Basic требуется всегда, кроме `/health`

Зрелость: core · Дата: 2026-09-16 · Источник: решение владельца

Логин и пароль спрашиваются независимо от адреса привязки.
Единственное исключение — `SAFE_PUBLIC_PATHS = {"/health"}`.

Расхождение с кодом на 2026-09-16: `_auth_required()` возвращает `False`
при локальном `app_host`, а туннель (`deploy/tunnel.sh`) открывает
такой сервер наружу без пароля. Фикс — задача `SEC-AUTH-ALWAYS`
в `docs/backlog.md`; до её выполнения правило главнее кода: новые
правки не должны опираться на «локально — значит без авторизации».

## `[SEC-DIGEST]` Пароли и токены сравниваются `hmac.compare_digest`

Зрелость: core · Дата: 2026-09-16 · Источник: `app/security.py`

Никаких `==` для секретов. При отказе — 401 с
`WWW-Authenticate: Basic`, без подсказок о том, что именно не сошлось.

## `[SEC-COMPANION-TOKEN]` Компаньон ходит с отдельным токеном

Зрелость: validated · Дата: 2026-09-16 · Источник: решение владельца

Машинные вызовы (`/api/companion/*`) подтверждаются собственным
токеном в заголовке, а не тем, что у них нет `Origin`/`Referer`.
Токен задаётся в интерфейсе, маскируется при показе и сравнивается
по `[SEC-DIGEST]`.

Расхождение с кодом на 2026-09-16: `_origin_matches()` возвращает `True`,
если оба заголовка отсутствуют — это было сделано ради
компаньона и снимает защиту от CSRF для всех POST. Заменить на
токен — задача `SEC-COMPANION-TOKEN` в `docs/backlog.md`.

## `[SEC-FORM-TOKEN]` У каждой формы есть скрытый `token`

Зрелость: validated · Дата: 2026-09-16 · Источник: `app/templates/*`

Без скрытого `token` сервер не найдёт сверку и ответит ошибкой.
Отдельного CSRF-токена пока нет — это известный риск, а не
пропущенная деталь.

## `[SEC-TOKEN-URL]` Токен сверки — пропуск, а не имя файла

Зрелость: validated · Дата: 2026-09-16 · Источник: `app/web/routers/result.py`

Ссылки вида `/result/{token}` и `/download/{token}` дают доступ к
данным сверки, поэтому: токен случаен, живёт не дольше
`RESULT_TTL_MINUTES`, не попадает в логи и не пересылается почтой.
Новые маршруты с токеном в адресе не добавляются без нужды.

## `[ASGI-PURE]` `SecurityMiddleware` — чистый ASGI

Зрелость: validated · Дата: 2026-09-16 · Источник: грабли (`docs/references/known-issues.md`)

Завёрнутый в `BaseHTTPMiddleware` промежуточный слой ломает выгрузку
файлов и длинные ответы. Работаем только с `scope`/`receive`/`send`.

## `[SEC-OTA-SUDO]` Обновление — удалённое выполнение кода по задумке

Зрелость: validated · Дата: 2026-09-16 · Источник: `deploy/sudoers-excelkro`

`POST /update/apply` забирает код из git и перезапускает службу, то есть
доступ к этому маршруту равен доступу к серверу. Поэтому:
прав через sudo ровно два (`excelkro-update@check`, `@apply`),
никаких произвольных команд в `Cmnd_Alias`, и ветка из формы
проверяется на безопасные символы до передачи в `git`.

## `[SEC-ERRORS]` Ошибка понятна ревизору и не выдаёт внутренностей

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

Русский текст с подсказкой, что делать. Никаких `Internal server
error`, трассировок, путей файлов и ответов внешних сервисов в
интерфейсе. Подробности — в журнал службы.
