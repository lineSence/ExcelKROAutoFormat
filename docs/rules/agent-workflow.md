# Правила: работа агента и разработка (`DEV-*`)

## `[DEV-MAIN-DEFAULT]` По умолчанию коммиты идут в `main`

Зрелость: core · Дата: 2026-09-16 · Источник: решение владельца

Мелкие и средние правки — прямо в `main`. Крупные правки (разбиение
модулей, смена поведения сверки, правки безопасности) — ветка и
PR с коротким описанием. Слитые ветки удаляются.

## `[DEV-TESTS-REQUIRED]` Правка поведения — всегда с тестом

Зрелость: core · Дата: 2026-09-16 · Источник: решение владельца

Любое изменение поведения сопровождается тестом в `tests/` в том же
коммите. Тесты работают без сети и без реальных файлов сверок
(см. `[AI-NO-NET-TESTS]`, `[DOM-NO-REAL-DATA]`). Кроме `pytest -q`, CI
обязан гонять `ruff check .` — линтер уже настроен в
`pyproject.toml`, но шага в `.github/workflows/ci.yml` пока нет — задача
`DEV-RUFF-CI` в `docs/backlog.md`.

## `[DEV-FILE-SIZE]` Файл кода ограничен по размеру

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

Один фаӥл — одна зона ответственности. Пределы для любого `.py`
в `app/`, `companion/`, `tests/`:

- цель — до 500 строк и до 20 000 байт;
- жёсткий предел — 800 строк или 25 000 байт, выше падает
  `tests/test_file_size.py`;
- новый функционал не дописывается в ближайший большой файл:
  берётся новый модуль с узкой задачей (как `app/core/sellers.py`).

Причина не в красоте: агент читает фаӥлы целиком и без поиска по
коду (`[DEV-NO-CODE-SEARCH]`); фаӥл на десятки килобаӥт съедает
контекстное окно и при перезаписи обрезается молча
(`[DEV-TOOL-TRUNCATION]`).

Унаследованные нарушители на 2026-09-16: `app/core/mail.py` (~43 КБ),
`app/core/format.py` (~38 КБ), `app/core/vision.py` (~37 КБ),
`app/core/refs.py` (~30 КБ). Они перечислены в `LEGACY` теста с
текущим размером: расти им нельзя, только уменьшаться. При
разбиении такого фаӥла публичные имена сохраняются реэкспортом
в старом модуле, чтобы импорты и тесты не поехали (образец —
`tests/test_split_compat.py`), и это крупная правка по
`[DEV-MAIN-DEFAULT]`. Строка `LEGACY` со временем обнуляется и новые
записи в неё не добавляются.

Шаблоны и `docs/` под это правило не попадают; для L0 есть
свой предел в `tests/test_sek.py`.

## `[DEV-DOCS-SAME-COMMIT]` Знание записывается вместе с кодом

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

Меняется поведение — правится правило в `docs/rules/`; появляются
грабли — строка в `docs/references/known-issues.md`; появляется
маршрут или модуль — правка `docs/references/architecture-map.md`.
Всё спорное сначала падает в `docs/memory/inbox.md`.

## `[DEV-CODE-WINS]` Код главнее записи, но расхождение фиксируется

Зрелость: core · Дата: 2026-09-16 · Источник: старый `agents_context.md`

Если код расходится с правилом, реальное поведение описывается
текстом «расхождение с кодом на дату» в самом правиле, а не
замалчивается. Исключение — правила со зрелостью `core`: там
правило главнее, а код подлежит исправлению.

## `[DEV-RULE-FORMAT]` Формат правила единый

Зрелость: core · Дата: 2026-09-16 · Источник: решение владельца

Правило = заголовок `## [TAG] Короткая формулировка`, затем строка
«Зрелость: core|validated|draft · Дата: YYYY-MM-DD · Источник: …»,
затем тело. Тег уникален во всём `docs/rules/` и проверяется
`tests/test_sek.py`. Тег в коммите и в сообщении агента называется
целиком, без пересказа.

## `[DEV-TOOL-TRUNCATION]` Длинные файлы отправляются по одному

Зрелость: validated · Дата: 2026-09-16 · Источник: грабли

Кириллица в экранированном виде занимает в шесть раз больше места,
и пакетная отправка может обрезаться молча. Файлы коммитятся
по одному, после длинного файла проверяется его конец.

## `[DEV-NO-CODE-SEARCH]` Поиск по коду в GitHub не работает

Зрелость: validated · Дата: 2026-09-16 · Источник: грабли

Индекс репозитория пуст, поиск по коду возвращает нуль
результатов. Навигация — чтение файлов по карте
`docs/references/architecture-map.md`.

## `[DEV-ASK-OWNER]` Спорное решение — вопрос владельцу

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

Агент сам пишет в `docs/memory/inbox.md` и продвигает записи в
`docs/rules/` со зрелостью `validated`. Перевод в `core`, смена
требований владельца, новые внешние сервисы и правки предметных
порогов — только после явного «да».
