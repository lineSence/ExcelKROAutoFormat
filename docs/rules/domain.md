# Правила: предметная область (`DOM-*`)

За каждым пунктом стоит требование бухгалтерии, а не вкус разработчика.
Пороги, цвета и состав столбцов меняются только по явному «да» владельца.

## [DOM-COLUMNS] Столбцы файла сверки фиксированы

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

| Столбец | Содержимое |
| --- | --- |
| A | код |
| B | наименование |
| C | характеристика (метка `не+` для излишка) |
| D | учёт |
| E | факт |
| F | итого, шт. |
| G | цена |
| H | сумма |
| I | сумма по учёту |
| J | разница сумм |
| K | документ движения |
| L (12) | служебный комментарий, сюда же пишется «нет фото» |

Лист с данными — `TDSheet` (настройка `SHEET_NAME`).

## [DOM-SURPLUS] Излишек не даёт плюса по сумме

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

У излишка `J = 0`. Заливка `FFC000`, в столбце C метка `не+`.

## [DOM-COLORS] Оформление строк

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

- Пересорт: рамка `medium` цвета `FF000000` вокруг ячейки `F`.
- Неполный пересорт и недостача: заливка `FFFF00`.
- Излишек: заливка `FFC000`.

## [DOM-THRESHOLD] Пороги схожести — настройка, а не константа

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

Авторешение — от 0,80. Полоса сомнения 0,70–0,90 уходит на ручную
сверку человеку. Подробности — `docs/06-resort-rules.md`.

## [DOM-NO-PHOTO] Пометка «нет фото» ставится на плюсующие строки

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

Пометку в столбце L получают все плюсующие строки (`F > 0`) без
подтверждённого снимка. Отмечается именно отсутствие фото, а не
наличие. Если в столбце уже есть текст — дописываем через запятую
(`photo_mark.apply()`).

## [DOM-REBUILD-MARKS] Пометки ставятся после каждой сборки

Зрелость: validated · Дата: 2026-09-16 · Источник: грабли проекта

Пересборка от исходника (в том числе `claims.apply`) пишет столбец 12
заново, поэтому строки с подтверждённым фото хранятся в `Job.photo_rows`,
а пометки проставляются заново после каждой сборки файла.
История — `docs/references/known-issues.md`.

## [DOM-EXPORT-BY-HAND] Выгрузка только по кнопке

Зрелость: core · Дата: 2026-09-16 · Источник: требование владельца

Готовая сверка уходит на рабочий компьютер только после всех
подтверждений и только по нажатию человека. Заливка входящего
файла из папки может быть автоматической.

## [DOM-WAREHOUSE] Склад берётся из шапки и связывает данные

Зрелость: validated · Дата: 2026-09-16 · Источник: код и грабли проекта

Название склада (`Job.warehouse`) служит связкой с письмами
ревизоров (`[AI-MAIL-MATCH]`) и именем архива снимков
`Фото_<склад>_<дата>.zip`.

## [DOM-SELLERS-FILE] Продавцы и часы могут прийти третьим файлом

Зрелость: validated · Дата: 2026-09-16 · Источник: требование владельца и образец выгрузки 1С

На странице загрузки кроме двух сверок можно добавить необязательный
файл `.xlsx` с продавцами и их часами (поле `sellers`).

- Формат выгрузки — `docs/01-input-1c.md`: текстовая строка — ФИО,
  следующая числовая — его часы; последняя числовая строка без ФИО —
  итог, в список он не попадает.
- Разбор живёт в `app/core/sellers.py` и ничего сам в файл сверки не
  пишет: он отдаёт `SheetMeta.sellers`, а шапку рисует `meta.write_sellers()` —
  тот же код, что и при ручном вводе.
- Если часы есть в файле, доли сразу считаются по часам
  (`share_mode = "hours"`).
- Файл продавцов — помощник, а не условие работы: сбой разбора
  помечает этап `sellers` как неудачный, а сверка собирается дальше;
  продавцов всегда можно вписать вручную на странице результата,
  и ручной ввод при пересборке важнее файла.

## [DOM-PREV-SELLERS] Продавец прошлой сверки узнаётся по виду строки

Зрелость: validated · Дата: 2026-09-16 · Источник: грабли проекта

Блок продавцов внизу готовой сверки нельзя искать «всё, что ниже
последнего итога»: у нижней группы строки итога может не быть, и тогда
в продавцы попадают её товары, а веса съезжают на соседние строки.

Продавец (`prev._seller_at`) — это строка, где:

- в столбце B текст, а не число и не формула;
- пустой столбец A и нет чисел в D, E, F, G — иначе это товар;
- строкой ниже в столбце B стоит число: его вес (часы или единица).

Мини-таблица «Перезачёт» и другие подписи (`SERVICE_LABELS`) обрывают
поиск: их ФИО — уже другой расчёт, иначе продавцы задваиваются.
