# 6. Автоматические пересорты

Пересорт — это ошибка сорта внутри одного бренда. Одна позиция в минусе, другая в плюсе. Денежного ущерба нет.

Главное правило учёта: **излишек никогда не считается в плюс**. Любая положительная сумма обнуляется. В итог идёт только недостача.

## 6.1 Исходные столбцы

| Столбец | Заголовок | Роль |
| --- | --- | --- |
| `B` | имя номенклатуры | из него берётся бренд |
| `C` | `Хар-ка` | сюда ставится метка `не+` |
| `F` | `Итого` | расхождение в штуках |
| `G` | `Цена` | справочно, точное равенство не требуется |
| `J` | `Разница сумма` | результат разбора |

## 6.2 Границы поиска

1. Поиск идёт только внутри одной группы товаров. Пары между группами запрещены.
2. Участвуют только строки данных, где `F` не равно нулю.
3. Строки шапок и итогов не участвуют.
4. Порядок строк не меняется. Поиск — только расчёт.

## 6.3 Бренд номенклатуры

Позиции одного бренда собираются в гроздь (кластер). **Вкус и другие варианты товара не учитываются.** Все варианты одного бренда в группе входят в одну гроздь.

### Шаг 1. Нормализация имени

1. Сжать пробелы, убрать крайние пробелы.
2. Привести к нижнему регистру.
3. Заменить `ё` на `е`, `й` на `и`.
4. Удалить знаки `.` `,` `"` `«` `»` `-` `/` `(` `)`.
5. Удалить слово типа товара в начале (`сигареты`, `стики` и другие из настройки).

### Шаг 2. Единая запись кириллицы и латиницы

Один и тот же товар встречается в двух записях, например `Виолет` и `Violet`. Поэтому:

1. Привести имя к латинице по таблице транслитерации.
2. Привести схожие буквы к общему виду (`k`–`c`, `f`–`ph`, `i`–`y`, двойные буквы в одну).
3. Сравнивать уже преобразованные имена.

### Шаг 3. Мера близости

Две позиции относятся к одному бренду, если верно одно из условий:

1. Совпадают первые два слова имени или больше.
2. Совпадает первое слово, а мера схожести полных имён выше порога (по умолчанию 0,80 по `SequenceMatcher`).

Связь переходная: если A связано с B, а B связано с C, все три идут в одну гроздь. Так разные вкусы одного бренда собираются вместе.

Порог и список слов типа товара задаются в настройке, без правки кода.

## 6.4 Расчёт по грозди

Для каждой грозди одного бренда в группе:

1. Посчитать итог количества: `итогF = сумма F всех строк грозди`.
2. Посчитать итог суммы: `итогJ = сумма J всех строк грозди`.
3. Выбрать случай по таблице 6.5.

Размер расхождения не важен. Пары `-1`/`+1`, `-2`/`+2`, `-3`/`+1` разбираются одним правилом. Равенство цен не проверяется, отклонения допустимы.

Суммы не пересчитываются. В `J` остаётся значение из 1С либо ноль. Произведение `количество × цена` программа не считает.

## 6.5 Действия по случаям

| Случай | Условие | Действия |
| --- | --- | --- |
| Пересорт | `итогF` ≥ 0 и в грозди есть и минус, и плюс | рамка вокруг `F` всех строк грозди; `J = 0` во всех строках; заливки нет; метки нет |
| Излишек | `итогF` > 0 и минусов в грозди нет | оранжевая заливка `F` (`FFC000`); метка `не+` в `C`; `J = 0` |
| Недостача | `итогF` < 0 | жёлтая заливка `F` и `J` (`FFFF00`) в минусовых строках; `J` из 1С остаётся без изменений; в плюсовых строках грозди `J = 0` и рамка вокруг `F` |

Дополнительное правило знака суммы: если после разбора итог `J` по грозди получается положительным, он обнуляется. Положительная сумма в итог группы не идёт никогда.

## 6.6 Вид рамки

Рамка пересорта: средняя (`medium`), чёрная (`FF000000`), по всем четырём сторонам ячейки `F`.

## 6.7 Порядок работы алгоритма

1. Взять строки группы с `F` не равным нулю.
2. Нормализовать имена (6.3).
3. Собрать грозди одного бренда, включая все вкусы.
4. Для каждой грозди посчитать `итогF` и `итогJ` (6.4).
5. Применить действия по таблице 6.5.
6. Записать строку отчёта по группе (6.8).
7. Записать сомнительные совпадения имён (6.9).

Правило этого раздела заменяет простую подсветку для всех строк, где `F` не равно нулю.

## 6.8 Отчёт по группам

После обработки сайт показывает таблицу по группам товаров:

| Столбец отчёта | Содержание |
| --- | --- |
| Группа товаров | имя группы из шапки блока |
| Пересорты, шт. | сумма разобранных штук |
| Пересорты, сумма | сумма обнулённых значений `J` |
| Недостача, сумма | итог `J` группы после разбора |
| Строк без пары | число строк, где пара не найдена |

Отчёт показывается только на странице. В файл отчёт не записывается.

## 6.9 Список сомнительных совпадений

Сайт выводит вторую таблицу для ручной проверки связей имён:

| Столбец | Содержание |
| --- | --- |
| Группа | имя группы товаров |
| Имя 1 | имя первой позиции и номер строки |
| Имя 2 | имя второй позиции и номер строки |
| Мера схожести | число от 0 до 1 |
| Решение | `связаны` или `не связаны` |

В список попадают пары имён с мерой схожести в полосе около порога: от 0,70 до 0,90. Вывод справочный. На файл список не влияет. Человек смотрит его и правит файл вручную, если связь оказалась неверной.

Полоса задаётся в настройке.
