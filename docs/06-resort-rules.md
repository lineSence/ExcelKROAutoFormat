# 6. Автоматические пересорты

Пересорт — это пара позиций одного бренда. Одна позиция в минусе, другая в плюсе. Причина — ошибка сорта при продаже или приёмке. Денежного ущерба нет, если цены равны.

## 6.1 Исходные столбцы

| Столбец | Заголовок | Роль в поиске пересорта |
| --- | --- | --- |
| `B` | имя номенклатуры | из него берётся бренд |
| `C` | `Хар-ка` | сюда ставится метка `не+` |
| `F` | `Итого` | расхождение в штуках |
| `G` | `Цена` | условие равенства цен |
| `J` | `Разница сумма` | результат разбора |

## 6.2 Границы поиска

1. Поиск идёт только внутри одной группы товаров.
2. Рассматриваются только строки данных, где `F` не равно нулю.
3. Строки шапок и итогов не участвуют.
4. Порядок строк не меняется. Поиск пары — это только расчёт, а не сортировка.

## 6.3 Условие пары

Две строки образуют пару пересорта, если выполнены все условия:

1. Одинаковый бренд номенклатуры (см. 6.4).
2. Равная цена в `G`.
3. Противоположные значения в `F`: `-1` и `+1` (базовый случай).
4. Ни одна из строк ещё не вошла в другую пару.

## 6.4 Бренд номенклатуры

Имя в `B` имеет вид `<тип> <бренд> <вариант>`. Примеры из образцов:

- `Сигареты Некст Виолет`
- `Сигареты Русский стиль черный`

Сравнение имён делается после нормализации:

1. Убрать крайние пробелы, сжать двойные пробелы.
2. Привести к нижнему регистру.
3. Заменить `ё` на `е`.
4. Удалить знаки `.`, `,`, `"`, `«`, `»`, `-`.

Бренд = первые `N` слов после слова типа товара. Точное правило выделения бренда требует уточнения (вопрос Q26 в `04-open-questions.md`).

## 6.5 Действия при найденной паре

Для каждой строки пары:

1. Обвести ячейку `F` рамкой (вид рамки — вопрос Q27).
2. Записать в `J` значение `0`.
3. Жёлтую заливку не ставить.
4. Оранжевую заливку не ставить.
5. Метку `не+` не ставить.

Итог группы считается формулой `SUM` по `J`, поэтому пара пересорта на итог не влияет.

## 6.6 Действия для строки без пары

Смотреть на знак `F`:

| Знак `F` | Смысл | Заливка `F` | Метка в `C` | Значение `J` |
| --- | --- | --- | --- | --- |
| минус (`F` < 0) | недостача | жёлтая `FFFF00` | нет | значение из 1С (минус) |
| плюс (`F` > 0) | излишек | оранжевая `FFC000` | `не+` | `0` |

Дополнительно:

1. Для минусовой строки жёлтая заливка ставится также в `J` (по образцу).
2. Минусовая строка остаётся в итоге группы и даёт ущерб.
3. Плюсовая строка из итога убирается (`J = 0`), так как излишек не засчитывается в деньгах.

## 6.7 Порядок работы алгоритма

1. Собрать строки группы с `F` не равным нулю.
2. Сгруппировать их по ключу `(бренд, цена)`.
3. В каждой группе по ключу разделить строки на минусы и плюсы.
4. Соединять в пары по одной штуке, пока есть и минусы, и плюсы.
5. К парам применить 6.5.
6. К остаткам применить 6.6.
7. Записать отчёт: сколько пар найдено, сколько строк осталось без пары.

Правило этого раздела заменяет простую подсветку из шага 6 `03-transform-rules.md` для всех строк, где `F` не равно нулю.

## 6.8 Неясные случаи

1. `F` равно `-2` и `+2`, или `-3` и `+1`. См. Q28.
2. Три и более строк с одним ключом. См. Q28.
3. Разные цены у позиций одного бренда. См. Q29.
4. Пара в разных группах товаров. См. Q30.
