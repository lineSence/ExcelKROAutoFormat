# 6. Автоматические пересорты

Пересорт — это ошибка сорта внутри одного бренда. Одна позиция в минусе, другая в плюсе. Денежного ущерба нет.

Главное правило учёта: **излишек никогда не считается в плюс**. Любая положительная сумма обнуляется. В итог идёт только недостача.

## 6.1 Исходные столбцы

| Столбец | Заголовок | Роль |
| --- | --- | --- |
| `B` | имя номенклатуры | из него берётся бренд |
| `C` | `Хар-ка` | сюда ставится метка `не+` |
| `F` | `Итого` | расхождение в штуках |
| `G` | `Цена` | участвует в подборе пар (6.3.1) |
| `J` | `Разница сумма` | результат разбора |

## 6.2 Границы поиска

1. Поиск идёт только внутри одной группы товаров. Пары между группами запрещены.
2. Участвуют только строки данных, где `F` не равно нулю.
3. Строки шапок и итогов не участвуют.
4. Порядок строк не меняется. Поиск — только расчёт.
5. Цена проверяется при подборе пары по правилам 6.3.1. Цена позиции считается как `|J| / |F|`.

## 6.3 Бренд номенклатуры

Позиции одного бренда собираются в гроздь (кластер). **Вкус и другие варианты товара не учитываются.** Все варианты одного бренда в группе могут войти в одну гроздь.

### Шаг 1. Нормализация имени

1. Сжать пробелы, убрать крайние пробелы.
2. Привести к нижнему регистру.
3. Заменить `ё` на `е`, `й` на `и`.
4. Удалить знаки `.` `,` `"` `«` `»` `-` `/` `(` `)`.
5. Удалить слово типа товара в начале (список в настройке `TYPE_WORDS`).

### Шаг 2. Единая запись кириллицы и латиницы

Один и тот же товар встречается в двух записях, например `Виолет` и `Violet`. Поэтому:

1. Привести имя к латинице по таблице транслитерации.
2. Привести схожие буквы к общему виду (`k`–`c`, `f`–`ph`, `i`–`y`, двойные буквы в одну).
3. Сравнивать уже преобразованные имена.

### Шаг 3. Мера близости

Две позиции считаются **одним брендом**, если верно одно из условий:

1. Совпадают первые два слова имени или больше.
2. Мера схожести полных имён выше порога (`RESORT_SIMILARITY_THRESHOLD`, по умолчанию 0,80 по `SequenceMatcher`).

Одно общее первое слово брендом не считается. «Зажигалка Волки» и «Зажигалка USB» — разные бренды, так же их разделяет ручная сверка.

Связь переходная: если A связано с B, а B связано с C, все три идут в одну гроздь.

Порог и список слов типа товара задаются в настройке, без правки кода.

### 6.3.1 Допуск пары по цене

Ручная сверка связывает разные бренды только при сопоставимой цене. Поэтому:

1. Пара одного бренда (6.3, шаг 3) разрешена всегда, цена не проверяется.
2. Пара разных брендов разрешена, только если отношение `цена излишка / цена недостачи` лежит в границах `PRICE_GATE_LOW` … `PRICE_GATE_HIGH` (по умолчанию 0,95 … 1,50).
3. При выборе между несколькими возможными парами первыми берутся те, где излишек покрывает недостачу по деньгам (`цена излишка ≥ цена недостачи`).
4. При равных условиях предпочитается более похожее имя, равная цена, равное количество и соседство строк.
5. Решение пользователя по спорной паре отменяет проверку цены.

Если пары нет, строка остаётся одиночным излишком или недостачей.

## 6.4 Расчёт по грозди

Для каждой грозди в группе:

1. Посчитать итог количества: `итогF = сумма F всех строк грозди`.
2. Посчитать итог суммы: `итогJ = сумма J всех строк грозди`.
3. Выбрать случай по таблице 6.5.

Размер расхождения не важен. Пары `-1`/`+1`, `-2`/`+2`, `-3`/`+1` разбираются одним правилом.

Суммы не пересчитываются. В `J` остаётся значение из 1С либо ноль. Цена используется только для подбора пары, в файл она не записывается.

## 6.5 Действия по случаям

| Случай | Условие | Действия |
| --- | --- | --- |
| Пересорт | в грозди есть и минус, и плюс, и `итогJ` ≥ 0 | рамка вокруг `F` всех строк грозди; `J = 0` во всех строках; заливки нет; метки нет |
| Неполный пересорт | в грозди есть и минус, и плюс, но `итогJ` < 0 | рамка вокруг `F`; жёлтая заливка `F` и `J` (`FFFF00`); остаток суммы идёт в итог |
| Излишек | минусов в грозди нет | оранжевая заливка `F` (`FFC000`); метка `не+` в `C`; `J = 0` |
| Недостача | плюсов в грозди нет | жёлтая заливка `F` и `J` (`FFFF00`); `J` из 1С остаётся без изменений |

Дополнительное правило знака суммы: если после разбора итог `J` по грозди получается положительным, он обнуляется. Положительная сумма в итог группы не идёт никогда.

## 6.6 Вид рамки

Рамка пересорта: средняя (`medium`), чёрная (`FF000000`), по всем четырём сторонам ячейки `F`.

## 6.7 Порядок работы алгоритма

1. Взять строки группы с `F` не равным нулю.
2. Нормализовать имена (6.3).
3. Перебрать все пары «излишек — недостача», отбросить недопустимые по цене (6.3.1).
4. Взять пары по убыванию оценки, пока хватает количества недостачи.
5. Для каждой грозди посчитать `итогF` и `итогJ` (6.4).
6. Применить действия по таблице 6.5.
7. Записать строку отчёта по группе (6.8).
8. Записать состав грозди в отчёт (6.9).
9. Записать сомнительные совпадения имён (6.10).

Правило этого раздела заменяет простую подсветку для всех строк, где `F` не равно нулю.

## 6.8 Отчёт по группам

После обработки сайт показывает таблицу по группам товаров:

| Столбец отчёта | Содержание |
| --- | --- |
| Группа товаров | имя группы из шапки блока |
| Пересорты, шт. | сумма модулей `F` по разобранным строкам, делённая на 2 |
| Пересорты, сумма | сумма обнулённых значений `J` |
| Недостача, сумма | итог `J` группы после разбора |
| Строк без пары | число строк, где пара не найдена |

Счёт штук: пара `-1`/`+1` даёт 1 штуку, пара `-2`/`+2` даёт 2 штуки. При неровной грозди (`-3`/`+1`) число получается дробным, оно округляется до одного знака.

Отчёт показывается только на странице. В файл отчёт не записывается.

## 6.9 Отчёт о составе гроздей

Человек должен видеть, какие строки программа связала между собой. Поэтому сайт выводит состав каждой грозди. Вывод включается настройкой `REPORT_CLUSTER_MEMBERS`.

| Столбец | Содержание |
| --- | --- |
| Группа | имя группы товаров |
| Гроздь | номер грозди в группе и нормализованное имя бренда |
| Строка | номер строки в готовом файле |
| Имя | имя номенклатуры из `B` |
| `F` | расхождение в штуках |
| `J` до | значение `J` из 1С |
| `J` после | значение `J` после разбора |
| Решение | `пересорт`, `излишек` или `недостача` |

Грозди из одной строки показываются тоже: по ним видно строки без пары.

## 6.10 Список сомнительных совпадений

Сайт выводит таблицу для ручной проверки связей имён:

| Столбец | Содержание |
| --- | --- |
| Группа | имя группы товаров |
| Имя 1 | имя первой позиции и номер строки |
| Имя 2 | имя второй позиции и номер строки |
| Мера схожести | число от 0 до 1 |
| Решение | `связаны` или `не связаны` |

В список попадают пары имён с мерой схожести в полосе около порога: от 0,70 до 0,90 (`DOUBTFUL_MATCH_MIN`, `DOUBTFUL_MATCH_MAX`). Вывод справочный. На файл список не влияет. Человек смотрит его и правит файл вручную, если связь оказалась неверной.
