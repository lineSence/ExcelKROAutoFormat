# 4. Ответы и оставшиеся вопросы

Дата последних ответов: 11.09.2026.

## 4.1 Решено

### R1. Ручные данные

Все данные ниже вводятся вручную в Excel. Источники разные и вне файла 1С.

| Поле | Ячейка | Пример |
| --- | --- | --- |
| Неучтёнка | `B1` | `Неучтёнка 224,00` |
| Контрольное число | `C1` | `5299?` |
| Дата | `B3` | `17.08.2026` |
| Признак инвентаризации | `C5` | `Планово` |
| Итог с неучтёнкой | `I5` | `=I4+224` |
| Комментарий | `L` строки данных | `неучтёнка` |
| Строки товаров без кода | любое место | вставка вручную |
| Блок сотрудников | подвал, `B` и `C` | ФИО и число |

Метка `не+`, обнуление `J`, цветные заливки и рамки ставятся автоматически (см. R8). Человек только проверяет результат.

### R2. Среда работы

Веб-приложение на Python. Сервер: Ubuntu Server. Подробности: `05-architecture.md`.

### R3. Граница работы сайта

1. Сайт делает преобразование файла и показывает отчёт по группам. Форм для ручных полей нет.
2. Список сотрудников в базе не хранится.
3. Входа по паролю нет.
4. История файлов не хранится.
5. База данных не нужна.

### R4. Доступ

1. Служба слушает только `127.0.0.1:8000`. Порт свободен.
2. Домена нет, HTTPS и Nginx не нужны.
3. Доступ через SSH-туннель: `http://localhost:8000`.

### R5. Формат даты

В `B3` остаётся формат `mm-dd-yy` как в образце.

### R6. Подсветка расхождений

Заливка — постоянный стиль ячейки, без условного форматирования.

### R7. Строки данных

1. Порядок строк из 1С сохраняется полностью.
2. Пустые строки в группы не добавляются.

### R8. Автоматические пересорты

1. Поиск только внутри группы товаров.
2. Бренд — совпадение первых слов имени. Учитываются исключения: кириллица и латиница, мелкие вариации записи.
3. Размер расхождения не важен. Равенство цен не требуется.
4. Если итог количества по бренду положительный или нулевой — это пересорт: рамка вокруг `F`, `J = 0`, заливки нет.
5. Излишек никогда не считается в плюс. Положительная сумма обнуляется.
6. Чистый излишек без минусов: оранжевая заливка, метка `не+`, `J = 0`.
7. Недостача: жёлтая заливка, `J` из 1С остаётся в минус.
8. Рамка пересорта: средняя чёрная.

Полное правило: `06-resort-rules.md`.

### R9. Отчёт на странице

Сайт выводит таблицу по группам товаров: пересорты в штуках и в сумме, недостача, число строк без пары. В файл отчёт не записывается.

## 4.2 Осталось уточнить

### Q32. Гроздь с многими вариантами

Если у одного бренда много разных вариантов (вкусов), считать пересорт по всему бренду сразу, или только по близким парам вариантов?

### Q33. Сумма недостачи при разных ценах

Если итог количества отрицательный, какую сумму ставить в `J`: сумму из 1С как есть, или пересчитанную как `недостача в штуках × цена`?

### Q34. Порог схожести имён

Порог 0,80 — рабочее значение. Надо ли выводить на странице список сомнительных совпадений для проверки?
