# Интерфейс, настройки и обновление

## Режим разбора по умолчанию

На главной странице в блоке **«Режим разбора по умолчанию»** можно выбрать вариант,
который будет автоматически подставляться при новой загрузке сверки:

- `off` — только детерминированная логика;
- `model` — логика + локальная обученная модель;
- `llm` — логика + LLM-судья.

Выбор сохраняется через `POST /settings/default-mode` в `runtime.json` и переживает
перезапуск службы. Это именно **значение по умолчанию**: перед конкретной загрузкой
пользователь может выбрать другой режим.

Если сохранённый режим сейчас недоступен (например, модель не обучена или нет ключа
LLM), интерфейс не блокирует остальные варианты. Проверка готовности конкретного
режима выполняется при построении формы загрузки.

## Индикаторы выполнения

Общий `app/static/ui.js` автоматически добавляет обратную связь всем POST-формам:
кнопка блокируется, её текст меняется на «Выполняется…», а под формой появляется
анимированная `.loading-strip`. Это защищает прежде всего от двойного клика по
долгим операциям загрузки, обучения, проверки почты и обновления.

Формы могут отключить автоматический индикатор атрибутом
`data-no-loading="true"`. JavaScript не меняет данные формы и не требует сборщика.

Страница хода разбора (`/upload/progress/<ticket>`) и страница обновления имеют
дополнительные серверные индикаторы: сервер показывает реальный этап и состояние,
а не только факт отправки формы.

## Сворачивание больших списков

Чтобы служебные страницы не превращались в длинную ленту, `ui.js` сворачивает
элементы только на уровне представления:

- `.facts` с более чем 8 строками → `<details>`;
- более 5 вложенных карточек внутри одной `section.card` → `<details>`;
- таблицы с более чем 15 строками → `<details>`.

Ни один элемент не удаляется из страницы: содержимое переносится внутрь раскрываемого
блока. Порог выбран для первого экрана и не связан с ограничениями backend.

## Ветка обновления

На странице `/update` выбор **«Ветка обновления»** показывает ветки, которые известны
локальной копии Git:

1. удалённые `origin/*`;
2. локальные ветки;
3. `main` всегда присутствует в списке.

Выбранная ветка сохраняется в
`/var/lib/excelkro/update/selected-branch` (или в `${UPDATE_DIR}/selected-branch` при
нестандартном каталоге). Файл создаётся с правами `0600` и записывается атомарно.

Проверка имени ветки выполняется до обращения к Git. Запрещены пустые имена,
`..`, начальная `/` или `-`, конечный `/` и символы вне безопасного набора Git-ref.
Кроме того, `set_branch()` разрешает только ветку, реально присутствующую среди
доступных локальных или `origin`-веток.

После выбора `check` сравнивает именно выбранную ветку, а `apply` переводит рабочее
дерево на её `FETCH_HEAD`. Поэтому выбор ветки — не фильтр отображения: **это ветка,
на которую будет переведён сервер при установке**.

Текущий результат обновления содержит имя ветки. Если ранее записанное состояние
относится к другой ветке, счётчик новых коммитов для новой ветки не используется,
чтобы старое состояние не выглядело как актуальная проверка.

## Что остаётся неизменным

UI-слой не меняет формат Excel, правила пересортов или логику второго слоя. Все
новые настройки остаются в существующей модели хранения `runtime.json`; ветка OTA
хранится отдельно в каталоге состояния обновления, потому что сама программа может
быть переключена на другую версию до следующего запуска.
