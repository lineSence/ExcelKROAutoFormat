# 11. Почта ревизоров: приём фото и сообщений

Ревизоры присылают снимки плюсующего товара письмом. Раздел «Почта
ревизоров» (`/mail`) забирает такие письма из ящика, складывает вложения на
сервер и показывает, что удалось понять из текста. Решение по каждому
снимку по-прежнему принимает человек.

## Что нужно завести

1. Отдельный почтовый ящик для фото (по умолчанию Mail.ru). Основной
   рабочий ящик сюда подключать не стоит: пароль лежит в настройках службы.
2. **Пароль приложения** этого ящика, а не пароль от учётной записи.
   В Mail.ru он создаётся в настройках безопасности ящика, в Яндексе —
   в разделе «Пароли приложений».
3. Заполнить блок «Настройки ящика» на странице `/mail` и поставить
   галочку «Включить приём почты».

Никаких файлов на сервере править не нужно: все значения сохраняются
в `runtime.json` (см. `agents_context.md`, раздел 4).

## Настройки

| Поле формы | Ключ в `runtime.json` | По умолчанию |
| --- | --- | --- |
| Сервер IMAP | `mail_host` | `imap.mail.ru` |
| Порт | `mail_port` | `993` |
| Почтовый ящик | `mail_login` | пусто |
| Пароль приложения | `mail_password` | пусто |
| Папка ящика | `mail_folder` | `INBOX` |
| Адреса ревизоров | `mail_senders` | пусто (все) |
| Глубина поиска, дней | `mail_since_days` | `7` |
| Предел писем за заход | `mail_max_letters` | `20` |
| Предел снимков за заход | `mail_max_photos` | `40` |
| Предел размера снимка, МБ | `mail_max_photo_mb` | `15` |
| Ожидание сервера, секунд | `mail_timeout` | `30` |
| Хранить снимки, дней | `mail_keep_days` | `7` |
| Только непрочитанные | `mail_only_unseen` | да |
| Помечать прочитанными | `mail_mark_seen` | да |
| Включить приём почты | `mail_enabled` | нет |

Пустое поле пароля означает «оставить как было». Отдельная кнопка
«Удалить пароль» стирает его из настроек. Пустой список адресов
записывается принудительно: иначе белый список нельзя было бы снять.

## Папки с русскими именами

Папку можно указать любую: «Отчёты», «Ревизия 2026», «INBOX/Фото».
Имена папок в IMAP передаются не в UTF-8, а в особой кодировке из
RFC 3501 (modified UTF-7), поэтому «Отчёты» уезжает на сервер как
`&BB4EQgRHBRErBEs-`. Этим занимаются `mail.encode_folder()` и
`mail.quote_folder()`; кавычки нужны для имён с пробелами.

Имя должно совпадать с тем, что видно в почте, включая регистр и букву
«ё»: для сервера «Отчёты» и «отчеты» — разные папки. Если папка не
найдена, программа перечисляет в сообщении настоящие имена папок ящика
(`mail.list_folders()`), так что нужное можно скопировать оттуда.
Вложенная папка пишется через разделитель ящика, обычно `/`:
`INBOX/Отчёты`.

## Как идёт заход в ящик

1. Кнопка «Проверить ящик» (`POST /mail/check`) — вход, открытие папки и
   подсчёт писем к разбору. Ничего не скачивается.
2. Кнопка «Забрать почту» (`POST /mail/fetch`) — вход, поиск писем
   (`UNSEEN` и/или `SINCE`), чтение каждого письма, сохранение вложений
   в `mail-photos/<номер письма>/NN-имя.jpg` (прочие файлы — с приставкой
   `doc-`), затем очистка снимков старше `mail_keep_days`.
3. Номера разобранных писем пишутся в `mail-state.json` (последние 1000),
   поэтому повторный заход то же письмо не тянет. Флаг «прочитано» для
   этого ненадёжен: ящик смотрит и человек.
4. Разобранные письма складываются к прежним и пишутся на диск в
   `mail-letters.json` (модуль `app/core/mail_store.py`, последние 50 писем).

## Где живёт список писем

Раньше письма жили только в памяти процесса (`MAIL_LETTERS` в
`app/main.py`), и это давало неприятный эффект: после перезапуска службы
или обновления список оказывался пустым, кнопки «Архив письма №…» на
странице сверки не показывались, а новый заход в ящик честно отвечал
«Новых писем нет» — их номера уже лежали в `mail-state.json`.

Теперь письма сохраняются в `mail-letters.json` рядом с остальными данными:

- в файл попадают номер, отправитель, тема, дата, текст, подсказки и пути
  к вложениям вместе с именами товаров, которые узнала нейросеть;
- сами снимки остаются в `mail-photos`, в JSON они не копируются;
- при старте службы список читается обратно, поэтому кнопки архивов видны
  сразу, без повторного захода в ящик;
- письмо, у которого на диске не осталось ни одного файла (снимки убрал
  срок хранения), при чтении отбрасывается: архив из него уже не собрать.

Письма забираются только по кнопке. Фоновый сбор не нужен: состояние
сверок живёт в памяти процесса, и складывать результат было бы некуда.

## Связка со сверкой и распознаванием

Модуль `app/core/mail_vision.py`. Порядок работы такой:

1. Ревизор присылает письмо, вы нажимаете «Забрать почту» — снимки
   ложатся на диск.
2. Вы загружаете файл сверки на главной странице. Сразу после сборки
   файла (`upload` в `app/main.py`) снимки всех известных писем
   уходят в `vision.recognize_all()` вместе со списком излишков этой
   сверки. Ждать и нажимать что-то ещё не нужно.
3. Каждому снимку письма проставляется имя узнанного товара
   (`Photo.title`), а ответы модели складываются в `PHOTOS` по токену
   сверки — те же карточки, что и при ручной загрузке фото на `/vision`.
   Подтверждает строки по-прежнему человек. Имена сразу сохраняются в
   `mail-letters.json`, поэтому перезапуск службы их не теряет.
4. Итог разбора пишется строкой сообщения на странице сверки
   (`mail_vision.summary()`): сколько снимков разобрано, либо почему
   разбор не пошёл — выключено распознавание, нет ключа, нет излишков.

При пересборке файла (подтверждение пар, ручные поля, заявки реестра)
снимки в модель второй раз не гоняются: отчёт переносится на новый токен.
Повторный разбор идёт только если его ещё не было — например, почту
забрали уже после загрузки сверки.

## Архив письма

Кнопка «Архив письма» стоит рядом с кнопкой скачивания готовой сверки
и на странице почты. Маршрут — `GET /mail/archive/{uid}?token=<сверка>`.
На странице сверки таких кнопок столько, сколько известно писем; если
писем нет вовсе, блок не показывается — сначала зайдите в ящик.

В zip-архив попадают:

- все снимки письма;
- все прочие вложения (документы, таблицы, PDF);
- файл `письмо.txt` — отправитель, дата, тема и полный текст письма.

Архив отдаётся **уже обработанным**: файлы названы товаром, который узнала
нейросеть при обработке сверки, например
`01-Молоко Домик в деревне 3,2%.jpg`. Если у всех снимков письма имя уже
есть, кнопка новых запросов к GigaChat не делает. Разбор запускается здесь
только как запасной вариант — когда почту забрали позже загрузки сверки.
Если распознавание выключено, ключа нет или сверка не открыта, файлы
сохраняют свои исходные имена — архив всё равно скачивается.

## Маршруты

| Маршрут | Что делает |
| --- | --- |
| `GET /mail` | страница раздела |
| `POST /mail/settings` | сохранение настроек, редирект 303 |
| `POST /mail/check` | проверка ящика без скачивания |
| `POST /mail/fetch` | заход за письмами и вложениями |
| `POST /mail/password/clear` | удаление пароля из настроек |
| `GET /mail/photo/{uid}/{name}` | отдача скачанного снимка |
| `GET /mail/archive/{uid}` | обработанный zip-архив письма с текстом и вложениями |

Имена файлов чистятся `mail.safe_name()`, а путь снимка дополнительно
сверяется с папкой `mail-photos`: письмо может принести имя вида
`../../etc/passwd`.

## Файлы данных

| Файл в папке данных | Что хранит |
| --- | --- |
| `mail-photos/<uid>/` | скачанные вложения письма |
| `mail-state.json` | номера уже разобранных писем и дата последнего захода |
| `mail-letters.json` | сами письма (тема, текст, подсказки, пути к вложениям, имена товаров) |

## Что бывает не так

| Сообщение | Причина |
| --- | --- |
| «Ящик не пускает: проверьте логин и пароль приложения» | введён основной пароль ящика вместо пароля приложения, либо приём по IMAP не включён в настройках ящика |
| «Папка «…» не найдена в ящике» | имя написано иначе, чем в почте (регистр, «е» вместо «ё», забытая вложенность). В том же сообщении перечислены настоящие имена папок — скопируйте нужное |
| «Папка «…» не открывается» | сервер отказал в доступе к папке: например, это не папка писем, а системный ярлык |
| «Почтовый сервер … не отвечает» | нет сети или закрыт порт 993 |
| «Новых писем нет» после переустановки | номера писем помнит `mail-state.json`; сами письма берутся из `mail-letters.json` и остаются на странице. Чтобы разобрать письма заново, удалите `mail-state.json` |
| «вложение … больше N МБ» | снимок крупнее `mail_max_photo_mb`; ревизору проще переслать его отдельным письмом |
| Нет кнопки «Архив письма» на странице сверки | писем нет: ящик ещё не забирали, снимки уже удалил срок хранения либо служба работает на старой версии — обновите её на `/update` |
| «Письмо не найдено» при скачивании архива | письма нет ни в памяти, ни в `mail-letters.json`: вложения удалены по сроку хранения. Нажмите «Забрать почту» ещё раз |
| «Снимки писем не разобраны: распознавание выключено или нет ключа» | включите распознавание и введите ключ на `/vision`; архив письма при этом всё равно скачивается |
| «Снимки писем не разобраны: в сверке нет излишков» | модели не с чем сравнивать — в файле нет плюсующих строк |

## Тесты

`tests/test_mail.py` работает без сети: вместо ящика подставляется
заглушка через аргумент `opener` у `mail.check()` и `mail.collect()`.
Проверяются разбор письма с вложением, подсказки из текста, белый список
адресов, чистка имён файлов, сохранение снимков, пределы, пропуск уже
разобранных писем, а также кодировка имён папок и сообщение со списком
папок, когда указанной папки в ящике нет.

Архив письма, поиск слов про список и ФИО продавца проверяются там же:
`mail.build_archive()` собирает zip со снимками, прочими файлами и
`письмо.txt`, а `mail.find_seller()` не берёт фамилию ревизора.

`tests/test_mail_vision.py` проверяет связку со сверкой тоже без сети:
распознаватель подставляется аргументом `recognizer` у
`mail_vision.recognize_letters()`. Проверяются простановка имён снимкам,
пропуск отсутствующих на диске файлов, понятные причины отказа (нет
ключа, нет излишков) и то, что сбой модели не ломает обработку сверки.

`tests/test_mail_store.py` проверяет память о письмах: запись и чтение
`mail-letters.json`, отбрасывание писем без файлов на диске и складывание
свежих писем с ранее известными.
