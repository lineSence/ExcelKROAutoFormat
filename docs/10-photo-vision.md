# 10. Фото плюсующего товара

Ревизоры присылают фото товара, который оказался в излишке. Программа
сравнивает снимок со строками сверки и предлагает человеку, к какой строке
этот товар относится. В файл сверки распознавание не пишет ничего.

## Что это решает

При плюсующем товаре нужно понять, что именно лежит на полке: номенклатуру
с упаковки ищут руками по длинному списку излишков. Фото + список строк с
`F > 0` сводят задачу к выбору из десятков вариантов, а не к узнаванию
товара «вообще».

## Как работает

1. Кандидаты — только строки сверки с излишком (`F > 0`), отсортированные по
   количеству. Число строк в запросе ограничено настройкой.
2. Снимок и список имён уходят в модель зрения одним запросом.
3. Модель возвращает текст, прочитанный на упаковке, и до трёх номеров строк
   с уверенностью.
4. Ответ проверяется по списку: строку не из списка модель предложить не
   может. Если номер не совпал, имя подбирается по прочитанному тексту через
   ту же нормализацию, что и подбор пересортов (`resort.normalize`,
   `resort.similarity`).
5. Человек отмечает верную строку. Ответ ложится в `data/vision-samples.jsonl`
   — по нему видно, где модель ошибается.

Правила разбора соблюдаются: вкус и вариант товара различать не требуется
(6.3), количество штук по фото не считается — оно берётся из `F`.

## Настройки

Все настройки задаются на странице «Фото товара» (`/vision`) и хранятся в
`data/runtime.json` рядом с переключателем эмбеддингов. В `.env` для
распознавания ничего добавлять не нужно, перезапуск службы не требуется.

| Настройка | По умолчанию | Смысл |
| --- | --- | --- |
| Включить распознавание | выключено | Пока выключено, фото разбирает человек |
| Ключ API | пусто | Ключ Google AI Studio, вводится в интерфейсе |
| Модель | `gemini-flash-lite-latest` | Самые щедрые бесплатные лимиты |
| Строк-излишков в запросе | 40 | Длинный список ухудшает выбор |
| Предельный размер снимка | 8 МБ | Больше — снимок отклоняется |
| Ожидание ответа | 60 с | Таймаут запроса |
| Повторов при сбое | 2 | Повтор только на 429 и 5xx |
| Пауза между снимками | 4 с | Бесплатный тир считает обращения в минуту |
| Порог подбора по тексту | 0,55 | Ниже — строка не предлагается |
| Предел кеша | 2000 снимков | При переполнении кеш начинается заново |

Ключ на странице целиком не показывается: видно только последние знаки.
Кнопка «Удалить ключ API» убирает его из файла настроек.

## Кеш

Ответы кешируются по SHA-256 снимка, набора кандидатов и имени модели
(`data/vision-cache.json`). Один и тот же снимок не уходит в API дважды:
это экономит бесплатный лимит и делает повторный разбор мгновенным.

## Отказы

Модуль не бросает исключений. Нет ключа, нет сети, исчерпан лимит, битый
ответ — всё это показывается на странице как предупреждение по конкретному
снимку. Работа со сверкой при этом не прерывается.

## Чего распознавание не делает

- не пишет в файл сверки и не подтверждает пересорты само;
- не считает количество товара по снимку;
- не заменяет ревизора: точность подсказки на реальных фото — порядка
  80–90 % по первой строке, поэтому верную строку отмечает человек.

## Почта

Приём фото прямо из почты не сделан: снимки загружаются вручную на странице
«Фото товара». Привязку письма к сверке (склад × дата) имеет смысл делать
тем же способом, что и поиск в справочниках, — отдельным шагом, когда
точность подсказок будет подтверждена на реальных фото.
