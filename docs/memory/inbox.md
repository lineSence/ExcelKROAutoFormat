# Входящая память (`inbox`)

Короткие наблюдения до того, как они стали правилами.
Этот файл пишет агент сам, без спроса.

## Когда записывать

1. Поведение оказалось не таким, как ожидалось.
2. Нашёлся обходной путь, который пришлось искать.
3. Поведение внешнего сервиса не совпало с документацией.
4. Владелец поправил решение или формулировку.

## Формат записи — три строки

```
### YYYY-MM-DD Короткая суть
- Ситуация: что делали и что произошло
- Причина: почему так работает
- Вывод: как делать впредь (кандидат в правило, тег — если понятен)
```

## Конвейер

- **REGISTER** — запись появляется здесь со зрелостью `draft`.
- **PROMOTE** — если наблюдение повторилось или подтверждено кодом,
  агент сам переносит его в `docs/rules/*.md` со зрелостью `validated`,
  удаляет запись отсюда и пишет строку в `docs/memory/journal.md`.
- **CORE** — перевод в `core` только по явному «да» владельца.
- После промоута агент сообщает: `📚 Promoted: [TAG] → docs/rules/…`.
- Когда правило первый раз применено:
  `🆕 Using recently promoted: [TAG]`.
- Владелец может отменить любое правило командой `/revoke [TAG]`.

## Лимиты

- Не больше **50** записей. Срока жизни нет: запись уходит только
  промоутом или как явно неверная.
- На 51-й записи агент сначала разбирает старые (промоут или
  удаление), потом пишет новую. Лимит проверяется
  `tests/test_sek.py`.
- Секретов, фрагментов сверок и имён товаров из реальных файлов
  здесь быть не должно (`[SEC-NO-SECRETS]`).
