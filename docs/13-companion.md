# Программа-компаньон на рабочем компьютере

Сервер с приложением стоит в сети и доступен через туннель. Сами
сверки из 1С ложатся в папку на рабочем компьютере, и готовые файлы
нужны там же. Компаньон закрывает именно эти две перевозки и ничего
больше.

## Как идёт работа

1. Компаньон видит в папке новый `.xlsx` и отдаёт его серверу.
2. Сервер разбирает сверку тем же конвейером, что и при загрузке с
   страницы: билет, этапы, токен готовой сверки.
3. Компаньон сообщает человеку, что сверка разобрана, и при желании
   открывает `/result/{токен}` в браузере.
4. Человек разбирает спорные пары, заявки и шапку. Компаньон в этом
   не участвует и ничего не подтверждает.
5. Когда всё готово, человек нажимает на странице сверки кнопку
   «Выгрузить на компьютер». Сверка попадает в очередь выгрузок.
6. Компаньон опрашивает очередь, забирает готовый файл и архив
   снимков, кладёт их в папку готовых сверок и отмечает выгрузку.

Опрос — не лень, а единственный вариант: туннель исходящий, сервер сам
до рабочего компьютера не достучится.

## Серверная часть

| Файл | За что отвечает |
| --- | --- |
| `app/state/exports.py` | очередь выгрузок в памяти: «ждёт → забирается → выгружено» |
| `app/services/exports.py` | один архив снимков на всё задание |
| `app/web/routers/companion.py` | машинные маршруты `/api/companion/*` |
| `app/web/routers/result.py` | кнопка «Выгрузить на компьютер» и отмена |

Маршруты:

* `POST /api/companion/jobs` — multipart `file`, при надобности `prev`,
  `strict`, `verify`, `logic`. Ответ: `{ok, ticket, name}`.
* `GET /api/companion/jobs/{билет}` — этапы разбора, `ready`, `token`.
* `GET /api/companion/exports` — очередь выгрузок.
* `GET /api/companion/exports/{токен}/result` — готовый `.xlsx`.
* `GET /api/companion/exports/{токен}/photos.zip` — архив снимков (404, если
  снимков нет — это не ошибка).
* `POST /api/companion/exports/{токен}/done` и `…/failed` — итог выгрузки.

Доступ закрывает `app/security.py`. Своего ключа у машинных маршрутов нет:
при внешнем адресе нужен тот же Basic-вход, что и для страниц, а через
туннель на `127.0.0.1` вход не требуется. Заголовок `Origin` компаньон не
посылает — проверка источника пропускает запросы без него. Если трогаете
`SecurityMiddleware`, сохраните это поведение.

## Программа на рабочем компьютере

| Файл | За что отвечает |
| --- | --- |
| `companion/config.py` | настройки из окна, `companion-state.json` |
| `companion/state.py` | память о отправленных файлах по sha256 |
| `companion/client.py` | разговор с сервером на httpx |
| `companion/worker.py` | один проход: `send_new`, `follow`, `take_exports` |
| `companion/ui.py` | значок в трее и окно настроек |
| `companion/__main__.py` | запуск, цикл и журнал |

Настройки задаются только в окне «Настройки» из трея — файлов окружения
у компаньона нет, как и на сервере. Пароль показывается только хвостом,
пустое поле значит «оставить как было».

Папки в настройках:

* папка со сверками из 1С — откуда берём;
* папка для готовых сверок — куда кладём файл и архив;
* папка для сданных исходников и папка для сбоёв — если не заданы,
  исходник остаётся на месте.

Запуск:

```
pip install -r requirements-companion.txt
python -m companion                работа со значком в трее
python -m companion --настройки   только окно настроек
python -m companion --раз         один проход и выход
python -m companion --без-трея    цикл без трея, только журнал
```

Настройки и журнал лежат в `%LOCALAPPDATA%\ExcelKRO`.

## Грабли

* Срок жизни сверки на сервере ограничен (`RESULT_TTL_MINUTES`), и этапы
  разбора тоже забываются. Если компьютер был выключен, сверку надо
  залить заново — компаньон покажет это подсказкой.
* Открытый в Excel файл трогать нельзя: спутники `~$имя.xlsx`
  пропускаются, а сам файл должен отлежаться `stable_seconds`.
* Один и тот же файл не уходит дважды: сравнивается sha256, а не имя.
* Файлы скачиваются в `.part` и потом переименовываются: в папку
  готовых сверок смотрят люди.
* Выгрузка никогда не начинается сама: без нажатой кнопки очередь
  пустая. Не превращайте компаньона в автомат: решения за человеком.
