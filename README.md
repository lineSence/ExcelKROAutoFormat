# ExcelKROAutoFormat

Программа автоматически форматирует Excel-сверки инвентаризации и ищет пересорты.

- Вход: файл сверки из 1С (`.xlsx`, лист `TDSheet`).
- Выход: файл сверки с подготовленным форматированием и разметкой расхождений.
- Реализация: веб-приложение на Python (FastAPI + openpyxl) на Ubuntu Server.
- Доступ: SSH-туннель, адрес `http://localhost:8000`.

## Контекст разработки (читать первым)

Главная память проекта — [`agents_context.md`](agents_context.md). Там собраны

## Справочники: причина, администратор, ревизоры

Программа берёт четыре поля из двух книг Excel:

| Поле | Источник |
| --- | --- |
| Причина инвентаризации | книга планирования, пересечение «магазин × неделя» |
| Администратор (управляющий группой магазинов) | столбец листа «Переучеты», иначе имя листа планирования |
| Ревизоры | фамилии в ячейке распределения (лист «Переучеты») |
| Проверяющий | настройка `DEFAULT_CHECKER`, по умолчанию Разумовский |

Правила работы:

- Ревизоры берутся только из распределения — это главный источник.
- Фамилии разворачиваются в полные ФИО по листам телефонов. При однофамильцах
  без инициала остаётся запись как в графике.
- Если пару «склад + дата» определить не удалось, поля остаются пустыми.
  Служебные сообщения в итоговую сверку не пишутся никогда; пометка
  «не определено» видна только на странице результата.
- Имена складов сравниваются без уточнений в скобках, регистра и знаков.
- Что именно не удалось подставить, видно дважды: в блоке «Данные справочников»
  на странице результата и в блоке ошибок на `/refs`. Консоль для этого не нужна.

### Страница `/refs`: ручная загрузка

Сервер не видит сетевую папку компании, поэтому книги загружает человек из браузера.

1. Откройте `http://127.0.0.1:8000/refs`.
2. В Проводнике откройте папку компании, например
   `\\termserver\office\КРО_03\ОБЩАЯ`.
3. Выберите книгу планирования («НОВ ПЛАНИРОВАНИЕ») и книгу графика
   («График Ревизий») и нажмите «Загрузить справочники».
4. Нажмите «Проверить книги» — на странице появится число складов и фамилий.

Можно загружать одну книгу или сразу две. Файлы ложатся в `REFS_DIR` под именами
`planning.xlsx` и `schedule.xlsx` и живут там до следующей загрузки. Повторять загрузку
нужно тогда, когда книги в папке компании меняются.

Автоматическое копирование по расписанию пока выключено: код остаётся в
`app/core/refs_sync.py` и понадобится, когда у сервера появится доступ к сетевой
папке компании.

## Второй слой проверки и режим обучения

Режим проверки пар выбирается на странице загрузки:

- **Только логика** — детерминированный подбор пар, результат повторяемый.
- **Логика + нейросеть** — модель судит только те пары, которые предложила логика:
  может снять пару или отправить её в спорные, но своих пар не добавляет.

Решение человека всегда главнее модели. Каждый ответ на странице результата попадает
в базу примеров, по ним модель переобучается на `/training`.

Подробно — в `docs/07-ml-verifier.md`.

### Права на запись

База примеров и модель лежат в рабочей папке проекта, служба должна иметь право в неё писать:

```bash
cd /opt/excelkro
mkdir -p data
sudo chown -R "$(stat -c '%U' /opt/excelkro/app):$(stat -c '%G' /opt/excelkro/app)" data
ls -ld data
```

Файлы: `data/verifier.json` — обученная модель, `data/train-samples.jsonl` — примеры.
При обновлении через `git pull` они не затираются, но перед обновлением их стоит скопировать:

```bash
cp -a /opt/excelkro/data /opt/excelkro/data.backup
```

### Эмбеддинги имён (необязательно)

```bash
venv/bin/pip install -r requirements-ml.txt
venv/bin/python scripts/export_embed_model.py   # создаёт models/rubert-tiny2-int8.onnx
```

На VPS с 1 ГБ памяти это необязательный шаг: без него всё работает, скорость выше.
Включать и выключать эмбеддинги можно на странице `/training` без перезапуска службы.

## Распознавание фото товара

Ревизоры присылают фото плюсующего товара. На странице `/vision` снимки
загружаются вручную, программа показывает подходящие строки сверки, а выбор
делает человек. При подтверждении в столбец комментария вписывается пометка
«есть фото».

Ключ и остальные настройки задаются только на самой странице `/vision`.
Подробно — в `docs/10-photo-vision.md`.

## Настройки

Все ключи с пояснениями — в `deploy/.env.example`. Самые важные:

| Ключ | Смысл |
| --- | --- |
| `MAX_UPLOAD_MB` | Предел размера загружаемого файла |
| `MAX_UNPACKED_MB` | Предел размера распакованного архива (защита от zip-бомбы) |
| `TMP_DIR` | Рабочая папка службы, по умолчанию `/var/lib/excelkro/work` |
| `RESULT_TTL_MINUTES` | Срок хранения готовых файлов |
| `DOUBTFUL_LIMIT` | Предел числа спорных пар в отчёте |
| `PRICE_GATE_LOW`, `PRICE_GATE_HIGH` | Границы отношения цен для пары разных брендов |
| `MATCH_MIN_SCORE` | Нижняя оценка пары пересорта |
| `STRICT_RESORT` | Режим «только чёткие пересорты» по умолчанию |
| `REFS_DIR` | Папка загруженных справочников |
| `DEFAULT_CHECKER` | Проверяющий по умолчанию |
| `REFS_CELL_REASON`, `REFS_CELL_ADMIN`, `REFS_CELL_CHECKER`, `REFS_CELL_AUDITORS` | Ячейки записи в готовом файле |
| `REFS_MATCH_MIN_SCORE`, `REFS_DAYS_AROUND` | Точность поиска склада и даты |
| `VERIFY_MODE` | `off` — только логика, `model` — логика + нейросеть (значение по умолчанию) |
| `VERIFY_REJECT`, `VERIFY_WEIGHT` | Порог снятия пары и вклад модели в оценку |
| `VERIFIER_MODEL_PATH`, `TRAIN_STORE_PATH` | Файл модели и база примеров |
| `TRAIN_EPOCHS`, `TRAIN_MAX_SAMPLES` | Параметры обучения |
| `EMBED_ENABLED` | Эмбеддинги имён; на VPS с 1 ГБ лучше оставить `false` |

Настройки распознавания фото в этот список не входят: они задаются только через
интерфейс на `/vision` и хранятся в файле состояния службы.

Рабочие папки старше `RESULT_TTL_MINUTES` удаляются сами при следующей загрузке.

## Быстрая установка на сервер

Нужно: Ubuntu Server 22.04 или новее, доступ по SSH, право `sudo`.
Замените `user@server` на свой адрес.

### Шаг 1. Команды на сервере

```bash
ssh user@server
sudo apt-get update
sudo apt-get install -y git python3 python3-venv python3-pip rsync
sudo mkdir -p /opt/excelkro
sudo chown "$USER:$USER" /opt/excelkro
git clone https://github.com/lineSence/ExcelKROAutoFormat.git /opt/excelkro
cd /opt/excelkro
chmod +x deploy/*.sh
./deploy/install.sh
curl -sS http://127.0.0.1:8000/health
exit
```

Ответ `{"status":"ok","version":"0.4.0"}` значит, что служба работает.

Служба работает от системного пользователя `excelkro`, данные лежат в
`/var/lib/excelkro/work`. Код в `/opt/excelkro` служба не меняет.

### Шаг 2. Справочники

После установки откройте `/refs` и загрузите две книги из браузера.
Монтировать сетевую папку на сервере не нужно.

### Шаг 3. Команда на своём компьютере

```bash
./deploy/tunnel.sh user@server
```

Туннель держите открытым и откройте в браузере `http://127.0.0.1:8000`.

## Туннель из Windows (PowerShell)

Сервер слушает только `127.0.0.1`, поэтому страница открывается через SSH-туннель.
В Windows 10 и 11 клиент SSH уже встроен, ничего ставить не нужно.

```powershell
ssh -N -L 8000:127.0.0.1:8000 user@server
```

Окно остаётся открытым и ничего не печатает — так и должно быть. Пока оно открыто,
в браузере работает `http://127.0.0.1:8000`. Туннель закрывается по `Ctrl+C` или
закрытием окна.

Если SSH на нестандартном порту или вход по ключу:

```powershell
ssh -N -p 2222 -L 8000:127.0.0.1:8000 user@server
ssh -N -i $env:USERPROFILE\.ssh\id_ed25519 -L 8000:127.0.0.1:8000 user@server
```

Туннель и сразу браузер:

```powershell
Start-Process ssh -ArgumentList '-N','-L','8000:127.0.0.1:8000','user@server'
Start-Sleep -Seconds 3
Start-Process 'http://127.0.0.1:8000'
```

Закрыть такой фоновый туннель: `Get-Process ssh | Stop-Process`.

### Если туннель не работает

| Признак | Причина и действие |
| --- | --- |
| `bind: Address already in use` | Порт 8000 занят другим туннелем. Закройте старое окно или `Get-Process ssh \| Stop-Process` |
| `Permission denied` | Неверный логин, пароль или ключ. Проверьте `ssh user@server` без туннеля |
| Окно открыто, но страница не грузится | Служба на сервере не работает: `ssh user@server 'systemctl status excelkro'` |
| `Connection timed out` | Сервер недоступен по сети или закрыт порт SSH у провайдера |

## Обновление версии

Простой путь — страница `/update` в самой программе: кнопки «Проверить
обновления» и «Установить последнюю версию». Подробно — в
`docs/09-ota-update.md`.

С своего компьютера, из папки репозитория:

```bash
./deploy/deploy.sh user@server
```

Или на сервере одной командой (приводит код к состоянию `main`, лечит расхождение веток):

```bash
cd /opt/excelkro && git fetch origin && git reset --hard origin/main && venv/bin/pip install -r requirements.txt && sudo systemctl restart excelkro && sleep 2 && curl -sS http://127.0.0.1:8000/health
```

### Полезные команды службы

```bash
sudo systemctl status excelkro     # состояние
sudo systemctl restart excelkro    # перезапуск
sudo systemctl stop excelkro       # остановка
journalctl -u excelkro -n 100      # последние записи журнала
```

Настройки лежат в `/opt/excelkro/.env` (образец — `deploy/.env.example`). После правки файла перезапустите службу.

### Если не работает

| Признак | Причина и действие |
| --- | --- |
| `curl` даёт ошибку соединения | Служба не запустилась. Смотрите `journalctl -u excelkro -n 100` |
| Страница не открывается в браузере | Туннель закрыт. Запустите `./deploy/tunnel.sh user@server` заново |
| `fatal: Need to specify how to reconcile divergent branches` | На сервере свои коммиты. Помогает `git fetch origin && git reset --hard origin/main` |
| Ошибка при `pip install` | Нет доступа в сеть с сервера. Нужен выход к PyPI или своё зеркало |
| Порт 8000 занят | Измените `APP_PORT` в `.env` и порт в `deploy/app.service` |
| Ответ 500 на загрузке | Подробности ошибки только в журнале службы |
| На странице `/refs` книга «не загружена» | Файл ещё не загружен или был больше `MAX_UPLOAD_MB` |
| Причина, администратор или ревизоры не определились | Смотрите блок ошибок справочников на `/refs` и блок «Данные справочников» на странице результата |
| Вариант «логика + нейросеть» недоступен | Нет файла модели. Обучите её на `/training` или проверьте `VERIFIER_MODEL_PATH` |
| Ошибка записи при обучении | Нет прав на папку `data`. Смотрите раздел «Права на запись» |

## Граница автоматизации

Программа делает автоматически:

- ремонт файла из 1С;
- разбор блоков групп;
- сдвиг шапки и геометрию;
- поиск пересортов и разметку строк (рамка, жёлтый, оранжевый, метка `не+`);
- проверку пар вторым слоем, если выбран режим с нейросетью;
- формулы итогов групп и общего итога;
- автофильтр и имя выходного файла;
- подстановку причины, администратора, проверяющего и ревизоров из справочников;
- запись ручных полей сверки (причина, продавцы, подписи), если они заполнены на странице результата.

Человек вписывает в Excel вручную: неучтёнку (`B1`), контрольное число (`C1`), дату (`B3`), итог с неучтёнкой (`I5`), комментарии столбца `L`. Также он загружает свежие книги справочников на `/refs`, проверяет решения программы по спорным строкам и поля, которые справочники не определили.
