# ExcelKROAutoFormat

Программа автоматически форматирует Excel-сверки инвентаризации и ищет пересорты.

- Вход: файл сверки из 1С (`.xlsx`, лист `TDSheet`).
- Выход: файл сверки с подготовленным форматированием и разметкой расхождений.
- Реализация: веб-приложение на Python (FastAPI + openpyxl) на Ubuntu Server.
- Доступ: SSH-туннель, адрес `http://localhost:8000`.

## Запуск на своём компьютере

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp deploy/.env.example .env
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. Проверка службы: `http://127.0.0.1:8000/health`.

## Проверка кода

Инструменты разработки лежат в `requirements-dev.txt` и в продакшн не ставятся.

pip install -r requirements-dev.txt
ruff check .

## Справочники: причина, администратор, ревизоры

Программа берёт четыре поля из двух книг Excel:

| Поле | Источник |
| --- | --- |
| Причина инвентаризации | книга планирования, пересечение «магазин × неделя» |
| Администратор (управляющий группой магазинов) | столбец листа «Переучеты», иначе имя листа планирования |
| Ревизоры | фамилии в ячейке распределения (лист «Переучеты») |
| Проверяющий | настройка `DEFAULT_CHECKER`, по умолчанию Разумовский |

Правила работы:

- Ревизоры берутся только из распределения — это главный источник.
- Фамилии разворачиваются в полные ФИО по листам телефонов. При однофамильцах
  без инициала остаётся запись как в графике.
- Если пару «склад + дата» определить не удалось, поля остаются пустыми.
  Служебные сообщения в итоговую сверку не пишутся никогда; пометка
  «не определено» видна только на странице результата.
- Имена складов сравниваются без уточнений в скобках, регистра и знаков.

### Страница `/refs`: ручная загрузка

Сервер не видит сетевую папку компании, поэтому книги загружает человек из браузера.

1. Откройте `http://127.0.0.1:8000/refs`.
2. В Проводнике откройте папку компании, например
   `\\termserver\office\КРО_03\ОБЩАЯ`.
3. Выберите книгу планирования («НОВ ПЛАНИРОВАНИЕ») и книгу графика
   («График Ревизий») и нажмите «Загрузить справочники».
4. На странице видно время загрузки, размер файлов, число складов и фамилий.

Можно загружать одну книгу или сразу две. Файлы ложатся в `REFS_DIR` под именами
`planning.xlsx` и `schedule.xlsx` и живут там до следующей загрузки. Повторять загрузку
нужно тогда, когда книги в папке компании меняются.

Автоматическое копирование по расписанию пока выключено: код остаётся в
`app/core/refs_sync.py` и понадобится, когда у сервера появится доступ к сетевой
папке компании.

## Настройки

Все ключи с пояснениями — в `deploy/.env.example`. Самые важные:

| Ключ | Смысл |
| --- | --- |
| `MAX_UPLOAD_MB` | Предел размера загружаемого файла |
| `MAX_UNPACKED_MB` | Предел размера распакованного архива (защита от zip-бомбы) |
| `TMP_DIR` | Рабочая папка службы, по умолчанию `/var/lib/excelkro/work` |
| `RESULT_TTL_MINUTES` | Срок хранения готовых файлов |
| `DOUBTFUL_LIMIT` | Предел числа спорных пар в отчёте |
| `PRICE_GATE_LOW`, `PRICE_GATE_HIGH` | Границы отношения цен для пары разных брендов |
| `MATCH_MIN_SCORE` | Нижняя оценка пары пересорта |
| `STRICT_RESORT` | Режим «только чёткие пересорты» по умолчанию |
| `REFS_DIR` | Папка загруженных справочников |
| `DEFAULT_CHECKER` | Проверяющий по умолчанию |
| `REFS_CELL_REASON`, `REFS_CELL_ADMIN`, `REFS_CELL_CHECKER`, `REFS_CELL_AUDITORS` | Ячейки записи в готовом файле |
| `REFS_MATCH_MIN_SCORE`, `REFS_DAYS_AROUND` | Точность поиска склада и даты |

Рабочие папки старше `RESULT_TTL_MINUTES` удаляются сами при следующей загрузке.

## Быстрая установка на сервер

Нужно: Ubuntu Server 22.04 или новее, доступ по SSH, право `sudo`.
Замените `user@server` на свой адрес.

### Шаг 1. Команды на сервере

```bash
ssh user@server
sudo apt-get update
sudo apt-get install -y git python3 python3-venv python3-pip rsync
sudo mkdir -p /opt/excelkro
sudo chown "$USER:$USER" /opt/excelkro
git clone https://github.com/lineSence/ExcelKROAutoFormat.git /opt/excelkro
cd /opt/excelkro
chmod +x deploy/*.sh
./deploy/install.sh
curl -sS http://127.0.0.1:8000/health
exit
```

Ответ `{"status":"ok","version":"0.2.0"}` значит, что служба работает.

Служба работает от системного пользователя `excelkro`, данные лежат в
`/var/lib/excelkro/work`. Код в `/opt/excelkro` служба не меняет.

### Шаг 2. Справочники

После установки откройте `/refs` и загрузите две книги из браузера.
Монтировать сетевую папку на сервере не нужно.

### Шаг 3. Команда на своём компьютере

```bash
./deploy/tunnel.sh user@server
```

Туннель держите открытым и откройте в браузере `http://127.0.0.1:8000`.

### Обновление версии

С своего компьютера, из папки репозитория:

```bash
./deploy/deploy.sh user@server
```

Или на сервере:

```bash
cd /opt/excelkro
git pull
venv/bin/pip install -r requirements.txt
sudo systemctl restart excelkro
```

### Полезные команды службы

```bash
sudo systemctl status excelkro     # состояние
sudo systemctl restart excelkro    # перезапуск
sudo systemctl stop excelkro       # остановка
journalctl -u excelkro -n 100      # последние записи журнала
```

Настройки лежат в `/opt/excelkro/.env` (образец — `deploy/.env.example`). После правки файла перезапустите службу.

### Если не работает

| Признак | Причина и действие |
| --- | --- |
| `curl` даёт ошибку соединения | Служба не запустилась. Смотрите `journalctl -u excelkro -n 100` |
| Страница не открывается в браузере | Туннель закрыт. Запустите `./deploy/tunnel.sh user@server` заново |
| Ошибка при `pip install` | Нет доступа в сеть с сервера. Нужен выход к PyPI или своё зеркало |
| Порт 8000 занят | Измените `APP_PORT` в `.env`; служба берёт адрес и порт из `.env` |
| Ответ 500 на загрузке | Подробности ошибки только в журнале службы |
| На странице `/refs` книга «не загружена» | Файл ещё не загружен или был больше `MAX_UPLOAD_MB` |

## Выкладка на сервер

```bash
./deploy/deploy.sh user@server   # копирование и перезапуск службы
./deploy/tunnel.sh user@server   # туннель на локальный порт 8000
```

Первая установка на сервере: `./deploy/install.sh` (создаёт окружение, пользователя и службу `excelkro`).

## Граница автоматизации

Программа делает автоматически:

- ремонт файла из 1С;
- разбор блоков групп;
- сдвиг шапки и геометрию;
- поиск пересортов и разметку строк (рамка, жёлтый, оранжевый, метка `не+`);
- формулы итогов групп и общего итога;
- автофильтр и имя выходного файла;
- подстановку причины, администратора, проверяющего и ревизоров из справочников.

Человек вписывает в Excel вручную: неучтёнку (`B1`), контрольное число (`C1`), дату (`B3`), итог с неучтёнкой (`I5`), комментарии столбца `L`, блок сотрудников. Также он загружает свежие книги справочников на странице `/refs` и проверяет решения программы по спорным строкам и поля, которые справочники не определили.
